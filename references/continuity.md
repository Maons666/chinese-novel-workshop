# 连续性与交付

核心是知道“什么文本有效、哪些事确实发生、谁知道什么”。需要多少记录取决于作品规模，不取决于模板数量。

## 接入已有工程

先读项目入口、进度及作者指定材料，列出文件映射：规则、偏好、大纲、有效正文、草稿、人物、时间线、伏笔、审阅与存档。已有文件能承担职责就复用；不改名、不搬迁、不新建平行权威目录。

真实工作区可能比摘要或 Git 版本更新。开始编辑前检查文件当前内容，保存修改前原稿，保留作者尚未被摘要吸收的改动。旧审阅只适用于当时版本；正文变了须复核受影响结论。

新项目按 [模板说明](../templates/README.md) 渐进建档。短篇可以全放一份简报；长篇再拆人物、时间线和线索。

## 事实层级

优先遵循项目自己的权威约定；没有约定时使用以下区分：

1. 作者当前明确决定及已经确认的设定修订。
2. 当前有效正文中已发生的事件。
3. 本轮连续草稿链中暂时发生的事件。
4. 大纲、未来计划、试写方案与推测。

上层与下层实质矛盾时列出证据。作者明确改设定可以成为新规则，但旧正文不会自动被改写；登记受影响范围和待修项。角色说法不是客观真相，计划也不是已发生事件。

## 写前按需组装上下文

读取当前硬约束、当前段落或章纲、上一章实际结尾、出场人物状态、相关时间与物品、到期或本章要推进的线索。涉及早期细节时回读原文锚点；只读压缩摘要不足以证明精确措辞、承诺或数值。

长篇可以保留单章摘要、阶段摘要与全书索引。摘要必须能回到正文；修订正文后标出失效摘要并更新相关条目，不反复压缩同一份旧摘要直至丢失来源。

## 草稿链与接受状态

使用“候选 / 活跃草稿 / 作者接受 / 被替代”等状态，沿用已有版本名称。没有项目约定时，阶段内可用有顺序的草稿版本和修改记录，不强制特定 I/F 编号。

- 一次连续写多章时，后章可以依赖**本批活跃草稿链**，须记录所依赖的前章版本；这些事实只在该分支暂时有效。
- 单独试写或未选中的方案不进入活跃草稿链，不更新正式事实。
- 作者接受或已有授权规定可定稿时，再更新对应正式状态。
- 作者否决或修改前章后，标记依赖它的后续稿件与状态需要复核，不继续沿用失效信息。

正文、摘要和事实更新前后对应，不能留下“正文改了但角色仍拿着旧物品”的状态。模型自审完成不等于作者接受。

## 追踪什么

必要时用 [状态模板](../templates/story-state.md)，只记录有后续价值的内容：

- 当前时间、地点、人物目标与关系。
- 角色认知：事实、来源、获知时点、相信或怀疑的程度。
- 物品、资源、能力、伤势及改变原因。
- 伏笔和承诺：埋设位置、读者所知、计划用途、实际进展。
- 未解决问题、待核资料、原作偏离及作者决定。
- 下一步任务和依赖版本，便于新会话接续。

不是所有细节都是伏笔；时间较长未出现也不等于必须立刻回收。只对真正的叙事承诺提示影响。

## 文件与版本

有写文件授权时，在项目指定位置保存；只请求聊天建议时默认在对话交付。修订现有稿件前按项目规则保留原始版本，不覆盖存档。比较原文与新文，确认修改范围没有扩张。

如果不具备文件权限，返回可保存的正文与更新内容，说明尚未落盘；不要声称后台已记住。Git 提交、推送与公开发布只按作者的单独明确要求执行，技能调用本身不是发布授权。

## 字数与核验

“字数”至少区分正文汉字数、非空白字符数与平台口径。统计前明确是否排除标题、批注和占位；平台如何计算需查当前说明或实际后台，不能自行等同。

本技能提供可选的 [只读统计脚本](../scripts/text_stats.py)：对指定 UTF-8 文件统计汉字与非空白字符，可选排除 Markdown 标题，报告 SHA-256。它不识别所有批注或工作标注，默认统计全文件，也不自动扩写、截断或评判文笔。

交付时报告实际版本和检查范围。未运行统计就不要报精确字数；没有读完全文就不要宣布全书连续性通过。
