# 中文小说工坊 · Chinese Novel Workshop

一套可以随作者调整、**直接写出小说正文**的中文写作 Skill。先了解篇幅、已有构思、题材、文风、世界观、人物与合作方式，再完成构思、起稿、续写、重写和审阅。

支持原创与同人、短中长篇，以及从零开始、已有大纲或已有正文的作品。核心是 Markdown 指令与参考资料，可供能读取 Skill 的 agent 使用；不需要另购写作服务或配置模型 API。

## 它怎么陪你写

~~~mermaid
flowchart LR
    A[读取已有材料] --> B[只问必要的问题]
    B --> C[作者偏好与合作方案]
    C --> D[构思 / 规划 / 正文 / 改稿]
    D --> E[事实与结构审查]
    E --> F[中文表达与读者审阅]
    F --> G[范围内修订与状态同步]
    G --> C
~~~

**第一次使用**，它会分轮询问：

- 想写短篇、中篇还是长篇，是否有大致篇幅。
- 从零开始、只有想法、已有设定、已有大纲还是已经写了正文。
- 原创或同人，题材与主要阅读体验。
- 文风、视角、世界观、人物，以及确定不能改变的内容。
- 希望它提问陪写、共同规划、代拟初稿，还是只做审稿与编辑。

每轮最多三个简短问题。你已经说过的内容会保留，可以回答“不确定”“你推荐”或“先跳过”。有成熟工程时先读现有资料，不让你重新开书。

## 正文创作是核心能力

它可以从选定的构思直接写短篇，按大纲写完整章节，承接已有书稿续写，也可以按作者要求精修或重写。作者要求开始写、信息已经足够时，交付的是经过自查的实际正文，不会停在计划或建议。

~~~text
用 $chinese-novel-workshop 按我们确认的大纲写第一章。
直接给完整正文，保持第三人称限知和朴素语言，写后检查连续性。
~~~

作者也可以选择自己执笔，让 skill 只做规划或编辑；合作方式随时可改。可查看独立行为测试实际生成的 [完整短篇](evals/outputs/short-story.md) 和 [续写片段](evals/outputs/continuation.md)，对应要求与局限见 [验证记录](evals/validation.md)。

## 定制会改变什么

| 作者选择 | 方法随之改变 |
|---|---|
| 短篇，只有一个念头 | 聚焦一个主要变化，用简报与少量场景探索 |
| 长篇，已有大纲 | 保留已定节点，按当前卷与近期章节推进，追踪相关事实 |
| 想边写边找 | 小范围探索，写后整理实际发生的事，候选方向不自动定案 |
| 同人 | 先明确原作版本，区分官方事实、作者改动与待定二设 |
| 日常、关系、慢热 | 关注相处差异、情绪积累与生活变化，允许安静收尾 |
| 悬疑、冒险或成长 | 分别强化线索公平、行动条件或阶段成果的兑现 |
| 只想审稿 | 给出原文依据、影响与建议，不修改正文 |
| 想保留自己的笔法 | 从自己的样章与修改中学习，不用固定禁词和句长磨平风格 |

偏好保存在作品项目里，可以随时调整。硬约束、软偏好、暂定方案与本轮修改范围分开；详见 [定制方法](references/customization.md) 与 [作者偏好模板](templates/author-profile.md)。

## 安装

仓库根目录就是一个完整 Skill。克隆时保留 references、templates、agents 和 scripts，不要只复制入口。

**Codex / Windows PowerShell：**

~~~powershell
git clone https://github.com/Maons666/chinese-novel-workshop.git "$env:USERPROFILE\.codex\skills\chinese-novel-workshop"
~~~

**Codex / macOS、Linux：**

~~~sh
git clone https://github.com/Maons666/chinese-novel-workshop.git ~/.codex/skills/chinese-novel-workshop
~~~

目标目录已存在时先检查原安装，不覆盖里面的改动。安装后开启新会话，让宿主发现技能。也可放入一个项目的 .agents/skills/chinese-novel-workshop 目录，由支持该目录的宿主发现。

其他 agent：把整个目录放进其支持的 Skills 目录，或显式让它读取 [SKILL.md](SKILL.md)。这里只提供通用文件与 Codex 显示信息，没有依赖某个产品的专有 slash command、hooks 或多代理接口；其他宿主的发现机制以其文档为准。

## 开始使用

~~~text
请用 $chinese-novel-workshop 先了解我的写作意向，再决定怎么合作。
~~~

已有构思：

~~~text
用 $chinese-novel-workshop 陪我写一部中篇原创科幻。
我只有一个想法，想写温暖但克制的关系故事。先讨论，不要起正文。
~~~

已有工程：

~~~text
用 $chinese-novel-workshop 读取我现有的项目说明、大纲与进度。
已经确定的设定不要重新问，按当前大纲准备下一章，先给场景安排。
~~~

审稿与改偏好：

~~~text
只审第七章，不改文件。分别说清硬伤、可选建议与阅读感受。
后面希望描写更从容，但保持语言朴素；这次不要重写前文。
~~~

参见两个完整用法示例：[从一个想法开始](examples/short-original.md)、[接入已有长篇](examples/existing-long-project.md)。

## 审查与审阅

- **审查**：事实、因果、人物信息、时间、物品、世界规则、中文语病，以及题材专项问题。
- **审阅**：按这本书的目标观察节奏、情绪、人物声音、理解难点与继续阅读的动力。
- **输出**：区分确定问题、待核实和可选优化，引用实际读过的原文；也说明哪些表达应保留。
- **修订**：只在授权范围内执行。模型自查通过不等于作者接受，候选稿和活跃草稿不会自动成为正式设定。

没有统一的“好小说分数”，也不保证通过 AI 检测或获得平台流量。未执行的检查不会被记成已完成。

## 文件与依赖

~~~text
SKILL.md                  入口与任务路由
references/               访谈、方法、规划、正文、中文笔法、审阅、连续性、资料、定制
templates/                可裁剪的偏好、简报、章节任务、状态和报告
examples/                 独立编写的虚构用法示例
agents/openai.yaml        Codex 显示信息
scripts/                  可选只读统计与技能包校验
tests/                    脚本的确定性测试
evals/                    行为测试场景与实际验证记录
SOURCES.md                参考来源、版本与取舍
~~~

核心写作无需 Python。可选脚本使用 Python 3.10+ 标准库，无第三方依赖：

~~~sh
python scripts/text_stats.py path/to/chapter.md --skip-headings
python scripts/validate.py
python -m unittest discover -s tests -v
~~~

统计脚本报告汉字、非空白字符和文件 SHA-256。它只按选项排除 ATX 标题，批注与占位仍计入，不等同于任意平台的字数口径；汉字识别依据当前 Python 的 Unicode 数据库。脚本不改稿、不补字、不判断文学质量。

作品与个人资料应放在**自己的小说项目目录**。公开技能仓库只保存方法与虚构示例。短篇不用强建复杂目录，已有项目不用迁移。
