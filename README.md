# 中文小说工坊

**先了解你想写什么，再一起把它写出来。**

一套随作者调整的中文小说写作 Skill：从构思与大纲，到完整正文、续写、重写和审阅。支持原创与同人、短中长篇，也能接入已经写到一半的作品。

[样文](#先读一页)　[作者选择](#这本书由你决定)　[安装与调用](#安装然后开始写)　[审阅](#写完之后再读一遍)

## 先读一页

> 房东约了傍晚来收钥匙。老许把招牌卸下来，靠在墙边。退休以后，他早晨可以睡晚一些了，可想到明天不用开门，又不知道醒来该做什么。
>
> 柜底还压着两只旧钟，是他早年收来留作零件的。他擦掉一只小座钟上的灰，坐回工作台前，拆开钟壳，把损坏的零件换掉。
>
> 钟走起来时，一个女人在他耳边说：“那我走了。饭在锅里，你要是回来得晚——”

这段文字来自独立行为测试生成的 [完整短篇](evals/outputs/short-story.md)。也可阅读 [承接已有正文的续写片段](evals/outputs/continuation.md)，测试要求、实际覆盖范围与限制见 [验证记录](evals/validation.md)。

确定构思后，工坊可以直接交付短篇或完整章节；已有书稿可以接着写，也可以按作者要求精修或重写。你也可以自己执笔，只让它陪你规划或审稿。

## 这本书，由你决定

第一次合作，先读你已有的材料，再问仍然需要了解的事。

| 作者的选择 | 写作时据此调整 |
| --- | --- |
| 篇幅与起点 | 短篇、中篇或长篇；从一个念头开始，还是接着已有设定、大纲与正文推进 |
| 原创、同人与题材 | 明确主要阅读体验；同人先确认原作版本，区分官方事实、作者改动与待定二设 |
| 文风、视角与样章 | 结合自己的样章和修改理解笔法，保留人物声音与合适的表达 |
| 世界观与人物 | 记录已定规则、人物关系与不能改变的内容，写作时追踪相关事实 |
| 合作方式 | 提问陪写、共同规划、代拟初稿，或只做审稿与编辑；随时可以调整 |

每轮最多三个简短问题，可以回答“不确定”“你推荐”或“先跳过”。已经确认的内容会保留；成熟工程先沿用现有资料。

这些选择会改变方法：短篇围绕主要变化展开，长篇按当前卷与近期章节推进；边写边探索时，先小范围试写，再整理实际发生的事。日常与慢热看重相处和情绪的积累，悬疑、冒险与成长分别关注线索、行动条件与阶段成果。

偏好保存在**自己的作品项目里**。硬约束、软偏好、暂定方案与本轮修改范围分别记录，候选方向不会自动定案。详见 [定制方法](references/customization.md) 与 [作者偏好模板](templates/author-profile.md)。

## 安装，然后开始写

需要一个能读取 Skill 的 AI 宿主。核心由 Markdown 指令与参考资料组成，无需额外配置模型 API，也不需要 Python。

仓库根目录就是完整 Skill，安装时保留整个目录，包括 `references`、`templates`、`agents` 与 `scripts`。

**Codex / Windows PowerShell**

```powershell
git clone https://github.com/Maons666/chinese-novel-workshop.git "$env:USERPROFILE\.codex\skills\chinese-novel-workshop"
```

**Codex / macOS、Linux**

```sh
git clone https://github.com/Maons666/chinese-novel-workshop.git ~/.codex/skills/chinese-novel-workshop
```

目录已经存在时，先检查原安装与本地改动。安装后开启新会话，让宿主发现技能。也可安装在某个项目的 `.agents/skills/chinese-novel-workshop`，由支持该目录的宿主发现。

其他 agent 可以将整个目录放入其支持的 Skills 目录，或显式读取 [SKILL.md](SKILL.md)。仓库提供通用文件与 Codex 显示信息；其他宿主的发现机制以其文档为准。

第一次使用：

```text
请用 $chinese-novel-workshop 先了解我的写作意向，再决定怎么合作。
```

已经准备好起稿：

```text
用 $chinese-novel-workshop 按我们确认的大纲写第一章。
直接给完整正文，保持第三人称限知和朴素语言，写后检查连续性。
```

<details>
<summary>只有一个想法、已有工程，或只想审稿时</summary>

从一个想法开始：

```text
用 $chinese-novel-workshop 陪我写一部中篇原创科幻。
我只有一个想法，想写温暖但克制的关系故事。先讨论，不要起正文。
```

接着已有作品写：

```text
用 $chinese-novel-workshop 读取我现有的项目说明、大纲与进度。
已经确定的设定不要重新问，按当前大纲准备下一章，先给场景安排。
```

审稿，并调整之后的偏好：

```text
只审第七章，不改文件。分别说清硬伤、可选建议与阅读感受。
后面希望描写更从容，但保持语言朴素；这次不要重写前文。
```

完整用法见 [从一个想法开始](examples/short-original.md) 与 [接入已有长篇](examples/existing-long-project.md)。

</details>

## 写完之后，再读一遍

| 检查什么 | 如何处理 |
| --- | --- |
| 事实与结构 | 检查因果、人物信息、时间、物品、世界规则、中文语病及题材专项问题 |
| 阅读体验 | 按这本书的目标观察节奏、情绪、人物声音、理解难点与继续阅读的动力 |
| 问题与建议 | 引用实际读过的原文，区分确定问题、待核实与可选优化，也指出值得保留的表达 |
| 修订与状态 | 只在授权范围内改动，保留候选稿、活跃草稿与作者接受正文的区别 |

只要求审稿时，不修改正文。模型自查通过不等于作者接受；未执行的检查不会记成已完成。这里没有统一的“好小说分数”，也不保证通过 AI 检测或获得平台流量。

可选脚本使用 **Python 3.10+ 标准库**，无第三方依赖：

```sh
python scripts/text_stats.py path/to/chapter.md --skip-headings
python scripts/validate.py
python -m unittest discover -s tests -v
```

统计脚本报告汉字、非空白字符和文件 SHA-256；只按选项排除 ATX 标题，批注与占位仍计入。汉字识别依据当前 Python 的 Unicode 数据库，统计口径不等同于任意写作平台。脚本不改稿、不补字，也不判断文学质量。

</details>

作品与个人资料放在自己的小说项目目录，公开技能仓库只保存方法与虚构示例。短篇可以保留简单结构，已有项目无需迁移。

方法来源、版本与取舍记录在 [SOURCES.md](SOURCES.md)。包结构和脚本可自动检查；写作行为按场景验证，结构校验不代表写作效果实测。
